## FIRST30 — 1/10 vs 8/10

**The single biggest gap:** The first screen is inert — an invisible full-screen `.snl-setup__line` overlay eats every tap, so the count of taps to a live game is not 3, it is infinite. A mother in Nagpur taps the big green button, nothing happens, she taps it again, nothing happens, and she closes the tab. Ludo King's number is 3–5 taps; ours is a game that cannot be started by a human being.

**What the critic actually saw:**

The sanctioned probe timed out on run 1 (networkidle2, 45s) and passed on run 2 (loaded 3130ms, 52 drawCalls, 61058 tris, 463KB). My own instrumented run: DOMContentLoaded 1118ms, boot screen gone at 1768ms on a 4x-throttled phone, 27 requests, zero pending. Boot speed is fine.

Then I stopped trusting the probe and tapped the actual buttons. THE FIRST SCREEN ACCEPTS NO TAPS AT ALL. `document.elementFromPoint()` at the centre of every control on the setup card returns `.snl-setup__line`, never the button: "Start playing" — blocked. "2 players" / "3 players" / "4 players" — blocked. "Names, pieces and settings" — blocked. The हिं language chip — blocked. The sound chip — blocked. A real `touchscreen.tap()` on "Start playing" leaves the DOM byte-identical 5s later (`class="snl-setup is-in"`, card still present, no pageerror, no console error). Same for "2 players". Root cause measured: `.snl-setup__line` (setup.js line 512) is `position:fixed; inset:0; z-index:5; opacity:0` and sets `display:flex`, which beats the `hidden` attribute's UA `display:none` (author origin wins); index.html's reset has no `[hidden]` rule — I grepped. Computed style confirms `display:flex, opacity:0, visibility:visible, pointerEvents:auto, zIndex:5`, rect 0,0,390x844. An invisible full-bleed sheet sits over the whole product from first paint. Only `element.click()` (which bypasses hit-testing) starts the game — which is exactly why probe.mjs's setup scenario passes: it calls `window.__SNL.quickStart(2)` and never taps a pixel. The harness is blind to the only thing that matters.

Screenshots. The setup card at 390x844 and 360x640: IFM tree logo, "Saanp Seedhi" in Lora italic, a 12-word lead sentence, one teal gradient plaque ("Start playing" / "You and Mithu the parrot"), the label "or, with people in the room", three white 106x72 tiles reading 2/3/4 "players", an underlined text link, a mint-tinted "How to play" panel with four numbered 34px icons and four sentences, and a grey trust line. I counted the visible text nodes programmatically: 76 words, identical at 360x640, 375x667, 390x844 and 412x915. No scrolling at any size (good). Contrast measured OK (~4.9:1 and ~5.9:1 on the two dimmed lines).

There is not one picture of the game on the screen. The `.snl-setup__veil` is `rgba(255,255,255,.95) → rgba(247,250,249,.91) → rgba(224,243,240,.87)` plus a 3px blur; the code comment says "We soften it, never hide it" — it hides it. The lit 3D board behind is completely gone in the pixels. The only game imagery is four 34px glyphs bolted to sentences, and at 360x640 their teal number badges clip into the tiles above them.

The board itself (probe 02-board.png, reached via quickStart) shows the other half of the story: the board floats in the middle ~32% of the screen height with vast empty wood above and below, numerals are ~6px per digit and are overpainted by snakes and ladders ("94", "77", "74", "34", "47", "13", "30" all occluded), and there are TWO dice affordances competing — a 3D die on the table and a second die icon inside a full-width green "Roll" bar — under a text label that literally reads "Tap the dice", which DESIGN.md itself forbids.

## LANGUAGE — 3/10 vs 9/10

**The single biggest gap:** Hindi is a skin, not a language: i18n.js owns only chrome, so 86.6% of the words a Hindi player actually reads — every lesson body, every snake cost, every ladder action, all 35,376 characters of content.js — stay in English. REF-INDIA's fact #3 says 94% of households prefer Hindi for financial content; this game hands them Hindi buttons around English teaching.

**What the critic actually saw:**

probe.mjs got 2 shots then crashed ("Execution context was destroyed"), so I wrote my own driver: forced snl.lang='hi' pre-paint, played 44 turns, 44 lesson cards, 14 PNGs, and a DOM scanner measuring scrollHeight/clientHeight and computed font-size on every text node.

Plaques read Khiladi 1 / Khiladi 2 / Khiladi 3 at computed font-size 11.5px (DESIGN §13 floor is 16sp).

The lesson cards are the killer. 05: Hindi HUD, Hindi "चलो", Hindi "आप ने 4 डाला" — then the card says "Do chai roz / Two ₹30 chais a day is ₹21,900 a year. Measured: content.js is 35,376 chars of player-facing text and contains zero Devanagari codepoints. The hi table is 5,465 chars. In "Hindi" mode 86.6% of the words on screen are English.
